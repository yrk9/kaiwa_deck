# kaiwa_deck(会話デッキ)

TCG(トレーディングカードゲーム)の「デッキから1枚引く」を応用した、アイスブレイク用のWebアプリです。会話が止まったときに、お題のカードを1枚引いて、話のきっかけにします。

**公開URL**: https://kaiwa-deck-app.vercel.app (ログイン不要で、すぐに使えます)

## 解決したい課題

就活の懇親会や、顔見知りだけど話したことのない人との会話では、沈黙が怖くて、当たり障りのない話題で終わりがちです。「何を聞けばいいか思いつかない」を、カードを引くというゲームの行為に置き換えて、気軽に一歩踏み込んだ会話ができるようにしました。

背景と調査は [docs/課題とペルソナ.md](docs/課題とペルソナ.md) にまとめています。

## できること

- **ゲストですぐ使える**: 「はじめる」を押すだけで、登録なしで使えます(Supabaseの匿名ログイン)
- **デッキを作る**: 公式のお題を全部入れた状態で、1回の操作で作れます
- **自分のお題を作る・入れ替える**: 相手や場面に合わせて、デッキの中身を調整できます
- **ひとりで引く**: 山札からランダムに1枚ずつ引きます。同じお題は2回出ず、残りの枚数だけが見えます(まだ引いていないお題の中身は見えません)

複数人で同じ山札を引く「ルーム」の共有は、API(作成・参加・退出)まで実装済みで、画面とリアルタイムの同期は公開後に作ります。

## 技術スタック

| 役割           | 使ったもの                                                               |
| -------------- | ------------------------------------------------------------------------ |
| フロントエンド | Next.js(App Router)、TypeScript、Tailwind CSS、shadcn/ui、TanStack Query |
| バックエンド   | FastAPI(Python)、SQLAlchemy                                              |
| DB・認証       | Supabase(Postgres、Auth)                                                 |
| ホスティング   | Vercel(フロント)、Google Cloud Run(バックエンド)                         |
| ローカル開発   | Docker Compose                                                           |

```
ブラウザ ──▶ Vercel(Next.js) ──▶ Cloud Run(FastAPI) ──▶ Supabase Postgres
   │                                    │
   └── Supabase Auth でログイン ──────────┘ JWTを公開鍵で確かめる
```

BaaSだけで完結させず、FastAPIを挟んだのは、REST APIとDBの設計を自分で学ぶためです。選んだ理由は [docs/技術選定.md](docs/技術選定.md) にあります。

## 設計で意識したこと

- **自分のidをリクエストで受け取らない**: ユーザーのidは、すべて検証済みのJWTから取ります。他人になりすました操作を、APIの形の時点で防ぎます
- **idはすべてUUID**: デッキやルームのidはURLで共有するので、連番だと推測でほかの人のデータにアクセスされるおそれがあります
- **ネタバレしないAPI**: 山札は残りの枚数だけを返し、まだ引かれていないお題の中身は返しません
- **同時に引いても重複しない**: 「同じルームで同じお題は1回だけ」をDBの主キーで保証し、ぶつかったら選び直します
- **状態はDBに保存する**: Cloud Runは使われないと0台まで縮むので、進行中の状態をサーバーのメモリに持ちません
- **画面ごとにまとめて返すAPI**: ルーム画面に必要な情報を1回のリクエストで返し、フロントからの呼び出しを減らしています

詳しくは [docs/テーブル設計.md](docs/テーブル設計.md) と [docs/API設計.md](docs/API設計.md) を参照してください。

## 開発の進め方(AIとの分担)

Claude Code(AIのコーディング支援)と一緒に開発しました。どこを誰が作ったかをまとめます

**自分が担当したこと**

- 企画、課題の設定、ペルソナ、優先順位の判断(締め切りに合わせて「ひとりで引く」を先に公開する、など)
- 技術選定と設計の最終判断(テーブル・APIの設計は、Claudeと案を出し合い、レビューを重ねて決めました)

- デプロイの作業(Google Cloud、Vercel、Supabaseの設定)
- すべてのコミット(変更を自分で確認してから、手動でコミットしています)

**Claudeが担当したこと**

- バックエンド全体(API、モデル、テスト)

## ローカルで動かす

Docker Desktopと、Supabaseのプロジェクトが必要です(ローカルにNode.jsやPythonは要りません)。

1. Supabaseで、`supabase/migrations/0001_init.sql` を実行し、匿名ログインを有効にする
2. `backend/.env.example` と `frontend/.env.local.example` をコピーして、値を入れる(`backend/.env`、`frontend/.env.local`)
3. 起動する

```bash
docker compose up -d --build
```

4. 公式のお題を入れる

```bash
docker compose exec backend python -m seed.seed_cards
```

フロントは http://localhost:3000 、APIの一覧は http://localhost:8000/docs で開けます。テストやlintのコマンドは [CLAUDE.md](CLAUDE.md) の「コマンド」にあります。環境構築でつまずいた点は [docs/苦労話.md](docs/苦労話.md) にまとめました。
