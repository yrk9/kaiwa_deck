## 目指す構成(M8〜M10)

```
src/
├─ app/                          ページ。フォルダ名がURLになる
│  ├─ layout.tsx                 全ページ共通のレイアウト
│  ├─ providers.tsx              TanStack Queryなどの準備
│  ├─ page.tsx                   /           LP
│  ├─ decks/
│  │  ├─ page.tsx                /decks      デッキ一覧
│  │  └─ [id]/page.tsx           /decks/[id] デッキ詳細
│  └─ room/
│     ├─ new/page.tsx            /room/new   部屋を作る(M9)
│     └─ [id]/page.tsx           /room/[id]  ドロー画面(M9、M10)
├─ components/
│  ├─ ui/                        shadcn/uiの部品(自動生成。基本は直接編集しない)
│  ├─ decks/                     デッキの画面だけで使う部品
│  ├─ room/                      ルームの画面だけで使う部品(M9〜)
│  └─ Header.tsx など            複数の画面で使う部品
├─ hooks/                        データ取得などの処理(useAuth、useDecks など)
├─ lib/
│  ├─ supabase.ts                Supabaseクライアント(1か所で作る)
│  ├─ api.ts                     APIを呼ぶ共通関数
│  └─ utils.ts                   shadcn/uiが使う関数(自動生成)
└─ types/
   └─ api.ts                     APIレスポンスの型
```

## 置き場所の決め方

| 作るもの | 置く場所 |
|---|---|
| 1つの画面でしか使わない部品 | `components/<画面名>/` |
| 複数の画面で使う部品 | `components/`の直下 |
| shadcn/uiの部品の追加 | `components/ui/`(`docker compose exec frontend npx shadcn@latest add dialog`のように、コマンドで追加) |
| APIを呼ぶ処理 | `hooks/`(画面コンポーネントに、fetchを直接書かない) |
| 認証、API呼び出しの共通処理 | `lib/` |
| APIレスポンスの型 | `types/` |

## 知っておくこと

- **URL=フォルダ名**: `app/decks/[id]/page.tsx`が`/decks/abc`に対応する。`[id]`はURLの変わる部分で、`useParams`で取れる
- **`"use client"`**: ブラウザで動く部品(状態、トークン、TanStack Queryを使うもの)は、ファイルの先頭に書く。このアプリのページは、ほとんど必要
- **`@/`は`src/`の意味**: `import { api } from "@/lib/api"`のように書く
- **環境変数**: `NEXT_PUBLIC_`で始まるものだけ、ブラウザから読める(`.env.local`)

## 触らないファイル

- `AGENTS.md`、`CLAUDE.md`(`frontend/`直下): Next.jsが自動で作る・作り直す
- `components/ui/*`: shadcn/uiの生成物。見た目を変えたいときは、このファイルより、使う側で調整する
- `.next/`、`node_modules/`: 自動で作られる
