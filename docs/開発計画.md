# 開発計画

## MVPフェーズ分け

事前準備(デッキ/カードCRUD+ソロドロー)を先に作る。その場共有もソロドローと同じ抽選ロジックの上に成り立つため。ただしMVP完了時点では両方揃える。

- **MVP v0(基盤、目安2〜4週間)**: 認証、公式カードseed、デッキCRUD、ソロドロー体験+カードめくりアニメーション、ルーム内での引いた履歴表示(room単位、`drawn_by`なし)
- **MVP v1(公開版、+2〜3週間)**: ルーム作成・共有、リアルタイム同期ドロー、簡易プレゼンス表示
- **Phase 2(発展)**: `drawn_by`追加による`/history`本実装(個人がルームをまたいだ履歴+お気に入り評価)、お題のカテゴリ・spice_level(踏み込み度)対応、LLMパーソナライズ → PWA化 → コミュニティ投稿 → (必要なら)Go導入検討

## UI/UXでこだわるポイント

- カードめくり演出(Framer Motion、3D transform、山札の奥行き表現)
- ルーム内で全参加者が同時にめくれる演出(差別化の核)
- 空状態・ローディング状態の作り込み
- `prefers-reduced-motion`対応、モバイルファースト
- (Phase 2)カテゴリごとの色・アイコン区別、spice_levelの視覚化(星/アイコン)

## 開発の推奨進行順序

1. 要件確定・画面ラフスケッチ
2. プロジェクト初期化
3. DBスキーマ・マイグレーション、seedスクリプト
4. 認証実装
5. コアCRUD(カードライブラリ、デッキ)
6. ソロドロー体験+アニメーション
7. 履歴・お気に入り・評価機能
8. ルーム機能(リアルタイム共有)
9. 軽量E2Eテスト
10. デプロイ
11. 実際に使ってフィードバック反映
12. Phase 2着手

## 検証方法

- 複数セッションでの同時ドロー時に重複が起きないことを確認
- ゲスト利用→ソロドロー→デッキ編集の一連フローをブラウザで確認
- 複数ブラウザ/端末で同一ルームに入室し、片方が引いた瞬間にもう片方が同期することを確認
- 実際に初対面またはそれに近いシーンで使いドッグフーディング
